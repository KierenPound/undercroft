B.1  WHY THE QUERY IS CORRECT - TWO UNRELATED THINGS CALLED "THE SIGNATURE"

    Scheme        Where the signature lives                      Visible in
                                                                 unzip -l?
    -----------   --------------------------------------------   ----------
    v1 (JAR)      Files inside META-INF/ - MANIFEST.MF,          Yes
                  *.SF, *.RSA
    v2 / v3       A separate "APK Signing Block" between the     No - not a
                  file data and the central directory             file entry

An APK with zero META-INF signature files can therefore be fully signed.

Confirmed on this artefact: no *.RSA / *.SF / MANIFEST.MF entries are present
(see testing/apk_contents_evidence.txt), and the APK is nonetheless signed.

B.5  FINDING WORTH A DECISION - v3 SIGNING IS DISABLED

v3 is reported false. This is not an install or upload defect (Play App Signing
manages rotation on its own), but v3 is what enables key rotation with
proof-of-rotation. A v2-only APK carries no key-rotation lineage, so the signing
key could not later be rotated without changing app identity or establishing a
new signing lineage.

If rotation capability is wanted, enable it in the release signing config:

    enableV3Signing = true

Logged as a conscious decision point, not an error.
