# UnderCroft Design Principles

This note captures the product qualities we want to preserve as UnderCroft grows. It is not a marketing document. It is a working standard for design, UX writing, product decisions, and implementation tradeoffs.

## Core Aim

UnderCroft should help people manage estate preparation and bereavement admin in a way that feels calm, practical, and human. It must reduce overwhelm without becoming cold, and offer warmth without becoming vague.

## What We Are Protecting

### 1. Human Before Bureaucratic

The app deals with emotionally heavy work. Every screen should remember that.

- Pair practical admin with signals of memory, care, and personhood.
- Make room for photos, songs, letters, and personal context alongside formal tasks.
- Avoid clinical or detached presentation when a warmer tone can still be clear.

Test:
"Does this screen feel like it was made for a family going through something difficult, or just for a process?"

### 2. Clear, Concrete Guidance

When the app explains a task, it should help the user act, not merely understand.

- Break complicated processes into steps that can be followed in order.
- Prefer real-world specifics: names, forms, addresses, timings, contact methods, and next actions.
- Reduce ambiguity wherever possible.

Test:
"Could someone under stress read this and know what to do next?"

### 3. Warmth With Candour

The product voice should be kind, grounded, and honest.

- Use reassuring language without becoming sentimental.
- Use dry humour sparingly and only where it lowers anxiety rather than distracting.
- Do not hide difficult realities behind soft wording.

Test:
"Does this sound supportive and trustworthy, rather than corporate or overly polished?"

### 4. Practical Over Performative

Useful beats impressive.

- Prioritise features that unblock real estate tasks.
- Favour straightforward flows over decorative complexity.
- Let the app adapt to odd real-life situations rather than forcing users into rigid categories.

Examples:
- ad hoc data for unique household details
- editable placeholders instead of locked demo structures
- concrete financial guidance that anticipates cash-flow problems

Test:
"Is this helping with the actual work, or just making the interface feel busier?"

### 5. Low-Friction Interaction

Heavy subject matter already creates cognitive load. The UI should not add more.

- Prefer inline editing where it keeps tasks moving.
- Keep common actions obvious and close to the content they affect.
- Make uploads, previews, and data entry feel direct and forgiving.
- Minimise navigation hops for routine admin work.

Test:
"Does this flow feel calm and immediate, or does it make the user fight the interface?"

### 6. Privacy Must Feel Real

Security in UnderCroft is part of the user experience, not just an implementation detail.

- Protect sensitive data with measures that are visible in effect but not annoying in use.
- Keep biometric access, background timeout, and privacy protection reliable and predictable.
- Avoid security theatre. If a control adds friction, it must clearly earn that cost.

Test:
"Would a user trust this app with family and estate information after using it for five minutes?"

### 7. Consistency Builds Trust

The app should feel authored, not assembled.

- Keep layout patterns, interaction models, and copy tone consistent across modules.
- Reuse proven structures when they already work well.
- Preserve parity between similar screens unless there is a strong reason to diverge.

Test:
"Does this new screen feel like UnderCroft, or like a separate app living inside it?"

## Design Implications

When making product or UI decisions, prefer the option that:

- lowers anxiety
- increases clarity
- preserves dignity
- reduces admin effort
- keeps personal context visible
- protects sensitive information without slowing the user down unnecessarily

## Anti-Patterns To Avoid

- overly clinical copy
- vague guidance without next steps
- decorative UI that obscures tasks
- placeholder content that feels fake or generic
- security friction that interrupts routine use
- inconsistent module design that weakens trust
- features that look comprehensive but fail real edge cases

## Working Heuristic

If a choice is unclear, ask:

1. Does this make the task clearer?
2. Does this make the moment feel calmer?
3. Does this respect the emotional weight of the subject?
4. Does this reduce friction for the person actually doing the work?
5. Does this still feel unmistakably like UnderCroft?

If the answer to most of these is no, the idea probably needs to change.
